# JOB 业务理解与测试方案

> 用途：嘉为科技二面作业的第二半（CMDB 已完成，见 cmdb-test 目录）。
> 本文是《蓝鲸两件套业务理解笔记》的 JOB 篇 + JOB 端到端测试方案。
> 接口信息全部来自 bk-job 官方仓库 docs/apidoc（ESB 接口文档，50+ 个接口，已本地存档 apidoc/ 目录）。

## 一、JOB 是什么（一句话 + 一个类比）

**一句话**：JOB 是蓝鲸的"遥控器"——批量地对一堆服务器执行脚本、分发文件、跑定时任务。

**类比**：CMDB 是"花名册"（登记资产在哪），JOB 是"遥控器"（对着资产批量干活）。
花名册上没有的人，遥控器管不到；所以 JOB 的目标机器清单直接来自 CMDB。

**和裸 SSH 的区别**（面试常问）：
- SSH 是一台一台登，100 台点 100 次，结果靠人肉记录；
- JOB 是一次对 100 台同时下发，自动执行、日志全回收、高危命令能拦截、还能设成定时任务自动跑。

## 二、核心概念（人话版）

| 概念 | 类比 | 说明 |
|------|------|------|
| 脚本 | 菜谱 | 一段 shell/python 等代码，云化管理，多业务共享 |
| 脚本版本 | 菜谱的修订版 | 同一个脚本可以有 v1.0、v1.1，能上线/禁用/回滚 |
| 作业模板 | 套餐菜谱模板 | 把多个步骤（执行脚本+分发文件）编排好，沉淀成模板 |
| 执行方案 | 模板的"点餐单" | 由模板生成，可改参数；对外执行的是方案 |
| 作业实例 | 一次真实的执行 | 每执行一次产生一个实例，可查状态和日志 |
| 执行账号 | 用谁的身份干活 | Linux 的 root、Windows 的 administrator 等 |
| 定时任务 | 自动炒菜机器人 | 按 crontab 规则周期执行某个执行方案 |
| 高危命令检测 | 安检门 | 脚本里的危险命令（如 rm -rf）会被规则拦截 |

## 三、5 条核心链路（对应测试方案）

参照 CMDB 测试方案的 5 链路结构，JOB 也挑了 5 条最能代表业务能力的链路：

### 链路 1：脚本管理（建→版本→上线→删除）

**业务场景**：运维把常用脚本存进平台，做成版本管理，别的同事和定时任务都能引用。

**接口调用链**：
```
create_script(建脚本，同时创建首个版本)
    → get_script_list(出现在列表)
    → create_script_version(加新版本 v1.1)
    → get_script_version_list(版本列表有 2 条)
    → publish_script_version(上线 v1.1，状态变 1)
    → disable_script_version(禁用，状态变 3)【负面素材：上线才能禁用】
    → delete_script(删除脚本，级联删版本)
```

**可测点**：
- 同名脚本创建是否被拒
- 版本号重复是否被拒
- 上线状态流转：未上线(0)→已上线(1)→已下线(2)/已禁用(3)，非法流转是否拦截
- 删除脚本后版本列表是否同步消失（级联删除）

### 链路 2：快速执行（JOB 最核心能力）

**业务场景**：不存脚本、用完即走的一次性执行。比如临时查 100 台机器的磁盘占用。

**接口调用链**：
```
fast_execute_script(下发脚本)
    → 返回 job_instance_id + step_instance_id
    → get_job_instance_status(轮询查状态，直到 finished=true)
    → get_job_instance_ip_log(按主机查执行日志)
    → operate_job_instance(终止执行)【可选】
```

**可测点**：
- 脚本内容三种优先级：script_version_id > script_id > script_content（传多个时生效哪个）
- 脚本内容/参数必须 Base64 编码，不编码或编错会怎样
- 目标服务器四种指定方式：host_id_list / ip_list / dynamic_group_list / topo_node_list
- **端到端亮点**：dynamic_group_list 用的是 CMDB 动态分组 ID → 在 CMDB 里按条件圈好主机，
  JOB 里直接对这个分组执行，两平台真正串起来了
- 状态流转：执行中→成功/失败；失败日志能拿到错误原因

### 链路 3：作业编排（模板→方案→实例）

**业务场景**：重复性多步骤操作沉淀成模板，比如"发布流程 = 停服务 + 备份 + 部署 + 起服务"。

**接口调用链**：
```
get_job_template_list(查模板，模板创建在 Web 端做)
    → get_job_plan_list(查模板下的执行方案)
    → get_job_plan_detail(方案详情，拿全局变量)
    → execute_job_plan(启动方案，产生作业实例)
    → get_job_instance_list(执行历史里有这条)
    → get_job_instance_global_var_value(取实例全局变量的值)
```

**可测点**：
- 模板与方案是一对多：一个模板能派生出多个方案
- execute_job_plan 支持传全局变量覆盖默认值，验证变量真的生效
- 执行历史按业务隔离：A 业务的实例在 B 业务查不到

### 链路 4：定时任务（crontab 式周期执行）

**业务场景**：每天凌晨自动备份数据库、每周自动清理日志。

**接口调用链**：
```
save_cron(建定时任务，引用执行方案 job_plan_id + crontab expression)
    → 新建后默认"暂停"状态【关键默认值】
    → get_cron_list / get_cron_detail(列表与详情)
    → update_cron_status(启动，状态变 1)
    → delete_cron(删除)
```

**可测点**：
- 新建后默认暂停，不主动启动不会执行（安全设计）
- expression 与 execute_time 互斥：传两个会被拒
- expression 格式校验：不支持 `?`（和标准 cron 的差异）
- 定时触发的执行会出现在作业执行历史里

### 链路 5：账号管理与高危命令检测（安全线）

**业务场景**：管理服务器 OS 执行账号；设置高危命令黑名单，防止误操作搞垮生产。

**接口调用链**：
```
create_account(建系统账号，Linux 或 Windows)
    → get_account_list(出现在账号列表)
    → delete_account(删除)
check_script(单次检测脚本是否含高危语句)
create_dangerous_rule(建高危规则，正则匹配)
    → get_dangerous_rule_list
    → enable/disable_dangerous_rule(启用/停用)
```

**可测点**：
- Windows 账号必须传密码，Linux 可不传（参数校验）
- check_script 对 `rm -rf /` 这类危险命令能识别
- 停用高危规则后，危险脚本是否还能被拦截（预期：规则停用则不再拦截）
- 高危规则被触发的操作有拦截日志

## 四、JOB 与 CMDB 的关系（端到端这一环）

> 定位：两个系统平等对待、各自做全方位测试；"JOB 用 CMDB 的数据"只是
> 端到端（连块测）这一环，不是整个项目的灵魂。数据契约（业务 ID / 主机 ID /
> 动态分组 ID / 拓扑节点）是端到端维度下的对接点之一。

- CMDB 是数据底座：JOB 的目标主机、拓扑节点、动态分组全来自 CMDB
- JOB 是执行能力：CMDB 管"有哪些机器"，JOB 管"对这些机器干什么"
- **端到端场景（连块测这一环）**：
  `CMDB 建业务 → CMDB 导入主机 → CMDB 建动态分组按 IP 条件圈主机 → JOB 快速执行引用该动态分组 → 100 台机器同时执行脚本 → 查状态、查日志`
  这条链把两个平台的 6 个接口串起来，就是"端到端"的完整定义。

## 五、环境现状与落地路径

**已确认的事实**：
1. JOB 没有像 CMDB 那样的官方 standalone 单容器镜像——JOB 是 11 个微服务，官方只提供
   Kubernetes Helm 部署（要求 K8s 1.12+ / Helm 3+ / PV provisioner）
2. 官方部署文档明确："仅部署作业平台本身是无法正常工作的"，JOB 强依赖整套蓝鲸基础套餐：
   PaaS、用户管理、权限中心、APIGateway、CMDB、管控平台（GSE）
3. 蓝鲸提供"单机部署"模式（整套基础套餐一键装到一台 Linux 机器，官方文档 install_on_single_host），
   所以"单机部署不现实"这个说法不准确；准确说法是：JOB 无法像 CMDB 那样单容器轻量跑，
   只能整套部署，资源门槛高，对个人开发机（WSL / Docker Desktop）不划算

**可行路径：蓝鲸官方在线体验环境**
- 入口：https://bk.tencent.com/s-mart/online-env
- 体验范围：基础套餐全产品（CMDB、**作业平台**、权限中心、用户管理、标准运维、节点管理、流程服务）
- 申请方式：腾讯问卷（https://wj.qq.com/s2/11468731/8390/），一个工作日内邮件发放账号
- FAQ：https://bk.tencent.com/docs/document/6.0/166/12810

## 六、面试可讲的坑位（待环境验证后补充实测版）

以下基于文档分析，环境到位后逐条验证：

| # | 坑位 | 文档依据 |
|---|------|----------|
| 1 | 脚本内容/参数必须 Base64，多参数要整体编码再拼 | fast_execute_script 文档 |
| 2 | 脚本优先级 script_version_id > script_id > script_content | fast_execute_script 文档 |
| 3 | 定时任务新建后默认"暂停"，要 update_cron_status 才能跑 | save_cron 文档 |
| 4 | crontab expression 不支持 `?`，与 execute_time 互斥 | save_cron 文档 |
| 5 | 指定主机建议用 host_id_list，ip_list 已不推荐（云区域维度易踩） | fast_execute_script 文档 |
| 6 | 脚本版本状态机：0 未上线/1 已上线/2 已下线/3 已禁用 | create_script 文档 |
| 7 | Windows 账号必传密码，Linux 可不传 | create_account 文档 |

| 12 | 文档内部矛盾：save_cron 说不支持 `?`，但 get_cron_detail 返回示例含 `?`（待实测澄清） | save_cron vs get_cron_detail 文档 |
