# 蓝鲸双系统端到端测试平台建设规划

> 2026-08-22 定稿。目标：把 CMDB + JOB 的测试从"散装用例"升级为"端到端测试平台"，作为嘉为科技面试作业的核心交付物。

## 一、是什么

一个把「CMDB 建数据 → JOB 拿它执行 → 自动校验结果 → 出报告」整条链路自动跑起来的系统。性能、安全、参数边界、UI 测试全挂在一个入口下。

### 平台组成（6 模块）

| 模块 | 说明 | 依赖环境 |
|------|------|---------|
| 统一测试入口 | 一条命令跑全部场景，按分层标签筛选 | 否 |
| 场景编排 | 跨系统链路定义与复用（CMDB→JOB 场景矩阵） | 是 |
| 测试报告 | 跑完自动出 HTML 报告，有历史对比 | 否 |
| AI 用例生成 | apidoc 喂大模型，自动产用例草稿 | 否 |
| Web 界面 | 看报告、一键触发测试（FastAPI 单文件 web_app.py） | 否 |
| 性能/安全模块 | Locust 压测 + 越权/鉴权用例 + Playwright UI 冒烟 | 是 |

### 测试分层（金字塔，2026-08-22 落地）

分开测 vs 连块测不是二选一：L1 unit 打底 → L2 单系统链路分开测
（JOB 六链路 + CMDB 独立链路，故障隔离）→ L3 跨系统连块测
（场景矩阵按数据契约组织，抓集成缺陷）。详见
《2026-08-22-分开测还是连块测-双系统测试策略.md》。

当前规模：131 用例 / 119 函数（57 unit 全绿 + 74 环境层待账号激活）。

## 二、为什么

1. 面试作业直接对口：作业要求就是 CMDB+JOB 端到端测试，平台把这件事产品化。
2. 面试叙事升维：从"我写了用例"升级为"我搭了平台"，且每句都能现场演示。
3. 测试开发本职：搭测试框架/平台就是这个岗位的日常工作。

## 三、怎么办（四阶段路线）

分工原则：**代码由 AI 代写，本人负责三个动作——跑起来、看明白、问清楚**；面试前把话术背熟。

### 阶段 0：搭壳（8-22 至 8-23，不等账号）✅ 已完成 2026-08-22

| 任务 | 产出 | 验收标准 |
|------|------|---------|
| 统一测试入口 | runner 脚本 | 一条命令跑全部用例；支持按分层标签筛选 |
| HTML 报告 | pytest-html / Allure 报告 | 跑全部用例能出报告页面 |
| AI 用例生成器 | gen_cases.py | 输入一份 apidoc，输出可收集的 pytest 用例草稿 |
| 接口补全（38/38） | api_client.py | JOB 全部 ESB 接口封装完毕，6 条链路 |
| 参数边界模块 | test_job_boundary.py | 等价类+边界值+非法值三层递进 |
| 分开测 CMDB 链路 | cmdb_client.py + test_cmdb_core.py | CMDB 独立链路（业务→主机→拓扑→模型） |
| 连块测场景矩阵 | test_integration.py | 契约/联动/反向 8 用例（分层金字塔 L3） |
| 压测脚本 | locustfile.py | 只读接口压测（尊重共享环境黑名单） |
| Web 界面（提前） | web_app.py | 首页看分层+统计，一键跑测试、看历史报告 |

## 四、风险与缓冲

- 账号发放可能延迟 → 阶段 0 不依赖环境，照常推进。
- 体验环境不开 ESB 权限 → 切换 cookie 抓包走 Web API 通道（封装层已预留）。
- 时间不足时唯一可砍项：阶段 3 的 Web 界面。报告 + 统一入口已足够支撑面试叙事。
- 面试日期临近时：优先保阶段 1（真实环境跑通）+ 阶段 3 话术，阶段 2 压测可降级为单接口 demo。
