## 4. 测试体系（本项目最核心的设计）

### 4.1 用例数量真相

91 用例 = **32 passed + 59 skipped**。59 个 skip 全部是环境依赖用例
（需要真实体验账号 / 部署环境），**skip 是刻意设计，不是失败**——
没账号就诚实 skip，绝不造假绿。这是用户明确要求的底线。

### 4.2 marker 分层（pytest.ini 注册 11 个）

| marker | 含义 | 是否依赖环境 |
|---|---|---|
| unit | 纯本地逻辑 | 否 |
| platform | Web 平台层（见 4.4 递归陷阱） | 否 |
| script / fast_exec / plan / cron / account / file | JOB 各模块接口用例 | 是（需账号） |
| cmdb / integration | CMDB 查询、跨系统联调 | 是 |
| boundary | 边界测试 | 部分是 |

### 4.3 测试计划 PLANS（app/web_app.py 第 38 行）

```python
PLANS = {
    'smoke': 'unit and not platform',   # 冒烟：不等账号秒出
    'regression': 'unit or cmdb or integration',
    'job-only': 'script or fast_exec or plan or cron or account or file',
    'e2e': 'integration',               # 只跑连块测（见 web_app.py）
}
```

Web 平台"一键跑测试"支持按 plan 名执行，借鉴 MeterSphere 测试计划概念。

### 4.4 关键设计决策（另一个 AI 绝对不要动的地方）

1. **platform marker 防递归自引用**：Web 层测试（tests/test_webapp.py）
   里有"跑冒烟计划"的端到端用例，它会 subprocess 再起 pytest。
   若不把 web 层测试从 smoke 计划里排除，会无限递归 spawn 子进程直至超时
   （这是实际踩过 70 秒超时的 bug）。修复方案就是
   `pytestmark = [pytest.mark.unit, pytest.mark.platform]` +
   `PLANS['smoke'] = 'unit and not platform'`。**拆掉任何一半都会复发。**
2. **Web 层测试隔离**：tests/test_webapp.py 用 TestClient +
   monkeypatch `storage.DB_PATH` 指到临时库，绝不碰真实 data/platform.db。
3. **中文测试函数名**：用户偏好，保持即可，不要改成英文。
4. **Web 平台阶段 0 定位**："有脸可用"，FastAPI 单文件内嵌 HTML，
   不引入前端工程，零构建零依赖。
