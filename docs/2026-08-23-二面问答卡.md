# 二面问答卡（15 道必问 + 标准答案）

> 用法：面试前一晚背熟。每道题就记「考点 + 一句话答案 + 大白话展开」。
> 原则：只背你讲得清的部分，讲不清的宁可说"这块我还在补"。
> 所有答案都用大白话写，照着说就是人话，不背术语。

---

## A 组：动机与职业规划（面试官最担心你，务必背熟）

### 1. 你确定转测试开发吗？为什么？

**考点**：你是不是"看 AI 时代测试吃香才来凑数"。

**答案**：三个角色我分得清——开发做功能、测试找 bug 兜质量、测试开发是用写代码把"找 bug"自动化。我确定转，是因为我喜欢"把一个陌生系统摸清楚"的过程，像拿到一个新玩具照着说明书玩明白。而测试开发恰好就是"先搞懂系统、再设计怎么检查它"的岗位，最能满足我这个爱好。这次蓝鲸的作业我完整走了一遍：啃文档、理解业务、再设计用例去测，越做越喜欢。

**忌**：别说"测试比开发简单"、"AI 时代测试更重要所以转"。

### 2. 你的职业规划是什么？

**考点**：是不是真想清楚了路。

**答案**：短期一两年，把测试开发的地基打牢——自动化用例、接口测试、性能和安全测试都做熟。中期三五年，往"测试平台 / 质量保障"走，从"会执行测试"变成"能搭一套测试体系"。一句话：先做扎实的执行者，再做体系的搭建者。

### 3. AI 时代，测试会被取代吗？

**考点**：认知深度，别背"不会被取代"的空话。

**答案**：不会取代，但会改变。AI 能帮我把接口文档变成用例草稿（我项目里 `gen_cases.py` 就在干这个），但它判断不了"该测什么、结果对不对、业务有没有理解错"——这些要人。所以我的定位是"用 AI 提效，人来把关"，而不是被 AI 取代。

## B 组：岗位认知（基础题，答错直接出局）

### 4. 开发、测试、测试开发有什么区别？

**答案**：开发盖楼（让功能跑起来）；测试验房（专找 bug 兜质量）；测试开发是会写代码的验房师（把找 bug 自动化）。测试开发 = 开发能力 + 测试思维的交集。

### 5. 什么是测试用例？什么是断言？

**答案**：用例就是一条检查——一个动作 + 一个预期 + 一个判断。断言是用例里"对答案"那句，实际结果对不上预期就判失败。

### 6. 通过 / 失败 / 跳过有什么区别？

**答案**：通过=查了、正常；失败=查了、有 bug；跳过=这次还没查。关键是：跳过不是失败，是"诚实说这条我还没验证"。

### 7. HTTP 状态码 200 / 404 / 500 是什么？

**答案**：200=成功；404=找不到；500=服务器自己崩了。再补两个：401=没登录，403=没权限。用快递记：200 已签收、404 查无此地址、500 仓库着火。

### 8. 什么是覆盖率？

**考点**：基础概念，别把覆盖率神化。

**答案**：覆盖率 = 你的测试"跑到"了多少代码。代码 100 行、测试跑到 57 行，覆盖率就是 57%。它衡量"代码被跑到了没有"，但**高覆盖率不等于没 bug**——只能说明跑到了，不能说明结果都对。我项目当前 57%。

## C 组：业务理解（核心考察，看你会不会啃系统）

### 9. CMDB 和 JOB 分别是干嘛的？什么关系？

**答案**：CMDB 是"花名册"——登记公司有哪些服务器、在哪个业务、什么拓扑关系；JOB 是"遥控器"——对一堆服务器批量执行脚本、分发文件、跑定时任务。关系：CMDB 管"有哪些机器"，JOB 管"对这些机器干什么"，JOB 干活前要从 CMDB 拿目标机器清单。

### 10. 你测了 JOB 的哪些链路？

**答案**：6 条——脚本管理（菜谱库）、快速执行（临时点外卖）、作业编排（套餐菜谱）、定时任务（自动炒菜机器人）、账号+高危检测（工牌+安检门）、文件分发+SQL（快递+下命令）。

### 11. 什么是"数据契约"？为什么重要？

**答案**：就是两个系统之间"约定好的数据必须对得上"——CMDB 的业务 ID、主机 ID、动态分组 ID、拓扑节点，在 JOB 里要能对上。它是我"端到端"维度里的一种契约（不是整个项目的全部）：对不上，JOB 就会对着错误的机器干活，这是集成测试最容易漏的坑。我项目的本体是"对两个系统各自做全方位测试"，数据契约只是端到端这一环。

### 12. 分开测 和 连块测 是什么意思？

**答案**：分开测 = 两个系统各自单独测（故障隔离，出了问题好定位是谁的锅）；连块测 = 两个系统连起来测（抓集成问题，数据对不对得上）。我的 131 个用例就是这两层。

## D 组：测试思维（隐藏打分点）

### 13. 为什么你 131 个用例有 74 个跳过？

**答案**：那 74 个全是环境依赖用例，需要真实体验账号才能跑（账号还在申请）；另有 20 个是浏览器 UI 测试（要本机起浏览器）。我选择诚实标记"跳过"而不是造假绿——跳过是"还没查"，造假是"没查说查了"。这 74 个 skip 反过来证明我那 57 个"通过"是真的、可信的。账号到手我就跑全量回归。

### 14. 测试要测哪些方面？

**答案**：五个维度——功能（对不对）、性能（快不快）、安全（漏不漏）、边界（临界点崩不崩）、端到端（两系统连起来对不对）。这正是我项目"全方位测试"的五条线，全收在一个 Web 平台入口下。

### 15. 给你一个全新系统，你怎么开始测？

**考点**：学习能力 + 方法论（面试官最看重的一条）。

**答案**：四步——①先搞懂它是什么、解决什么问题（啃文档、看界面）；②挑出核心业务链路；③设计分层用例，正常+异常+边界都测；④落地成自动化 + 出报告。这次蓝鲸作业我就是这么干的：先啃 38 份接口文档，再梳理 6 条链路，再写 131 个用例。

## 附：面试时"答不上来"的救命话术

- 概念没学透：**"这块我在项目里见过、但还没系统学透，是我接下来要补的。"**（诚实，不扣分）
- 数据没跑出来：**"这个需要真实环境出数据，账号还在申请，方案和代码骨架我已经就绪。"**
- 被追问代码细节：**"这个文件主要是做 XX 的，具体到某一行我可以现场读给你看。"**（把球接回自己熟悉的地方）
