## 二、性能测试（详细）

### 2.1 目标

摸清 JOB / CMDB 只读接口的**性能基线**（响应时间、吞吐量），而不是压垮共享环境。

### 2.2 为什么只压"只读"接口（面试必讲）

1. 体验环境是**共享环境**，申请时明确黑名单警告——压写接口会污染共享数据（建脚本、执行任务堆积脏数据）；只读接口无副作用。
2. 只读接口（列表查询）恰恰是**线上高频接口**，压它们最有代表性。
3. 压测目标是"摸清基线"，不是"压垮环境"。

### 2.3 测试对象与场景（已在 `scripts/locustfile.py` 落地）

| 接口 | 权重 | 为什么选它 |
|------|------|-----------|
| `get_job_instance_list` 作业实例列表 | 5 | 带时间窗的**最重列表接口**，最有代表性 |
| `get_script_list` 脚本列表 | 3 | 高频元数据查询 |
| `get_account_list` 账号列表 | 2 | 高频元数据查询 |
| CMDB `search_business` 业务查询 | 1 | **跨系统读**，验证 CMDB 侧性能基线 |

### 2.4 指标

- **QPS**（每秒请求数）：吞吐能力
- **响应时间 P50 / P95 / P99**：分别代表"一半请求 / 95% 请求 / 99% 请求"的耗时，P99 是性能红线的关键指标
- **错误率**：业务失败也算失败（`result=false` 或 `code!=0` 会标记 failure，不把服务端报错误记成"压测通过"）

### 2.5 工具选择：Locust

- 纯 Python，和项目同语言，零学习成本
- 脚本化定义用户行为，天然表达"一个用户查列表"这种场景
- 自带 Web 面板，实时看 QPS / 响应时间曲线

### 2.6 现状

脚本就绪（`locustfile.py`），待账号到位后 `locust -f locustfile.py --host <ESB_HOST>` 即可出基线报告。

## 三、安全测试（详细，本次补齐）

### 3.1 六个安全维度

| 维度 | 测什么 | 用例形态 |
|------|--------|---------|
| 鉴权 | 无凭证 / 错误凭证能否调用接口 | 传空三件套 / 乱填 token，预期拒绝 |
| 越权 | A 业务能否访问 B 业务的资源 | 用 A 的 scope 去查 B 的脚本/实例，预期隔离 |
| 注入 | SQL 注入、命令注入 | 参数塞 `' OR '1'='1`、脚本内容塞危险命令 |
| 敏感信息 | 响应/日志是否泄漏 token、密码 | 检查返回体与日志无凭证明文 |
| 高危命令 | `rm -rf` 等危险脚本是否被拦 | 复用 JOB 高危命令检测能力（链路 5） |
| 平台自身 | Web 平台目录穿越、写操作越权 | 已有：报告文件名白名单、`/api/probe` 只读白名单 |

### 3.2 已落地 vs 待补

- **已落地**：Web 平台白名单只读（`/api/probe` 拒绝写操作）、报告文件名防目录穿越（`/report/{filename}` 白名单）——`tests/test_webapp.py` 有对应用例。
- **已具备能力**：高危命令检测是 JOB 原生能力（`check_script` + 高危规则），链路 5 已封装。
- **本次补齐**：鉴权、越权、注入、敏感信息四个维度的用例骨架（`tests/test_security.py`），环境到位即可执行。

### 3.3 接口调试白名单的设计原则

Web 平台「接口调试」只开放只读查询，写操作一律拒绝：

- **JOB 侧 4 个**：脚本（列表 / 版本 / 详情）+ 作业执行状态——JOB 最核心的两类资源。
- **CMDB 侧 7 个**：业务、主机、拓扑（集群+模块）、模型、动态分组——CMDB 数据底座的 5 个核心概念。

为什么只读不写：

1. **防误操作**：写操作（建脚本 / 执行任务 / 删账号）会改变真实数据，在线调试随手点容易搞坏环境；
2. **共享环境约束**：蓝鲸体验环境是共享的，写操作会污染共享数据。

## 四、参数范围 / 边界测试

`boundary` marker，等价类 + 边界值 + 非法值三层递进（`tests/test_job_boundary.py`）。

例：`fast_execute_script` 的脚本内容必须 Base64——测"不编码 / 编错 / 正确编码"三档；时间窗参数测"起止颠倒 / 超长 / 非法格式"。

## 五、交互式测试

两层含义：

1. **接口交互（已覆盖）**：`/api/probe` Postman 式在线调 JOB/CMDB 只读接口，即时看返回 JSON。
2. **UI 交互（规划）**：Playwright 走真实页面——登录体验环境 → 进作业平台 → 建脚本 → 断言页面元素。脚本待账号到位后补。

## 六、端到端 / 数据契约

`integration` 场景矩阵，围绕三个数据契约组织：

- **契约一致性**（只读）：JOB 的 `bk_scope_id` == CMDB `bk_biz_id`、`host_id` == `bk_host_id`、`dynamic_group_list[].id` == CMDB 分组 ID
- **业务联动**：CMDB 建业务 → 导主机 → 建动态分组圈人 → JOB 对分组批量执行
- **隔离反向**（负面）：CMDB 不存在的幽灵主机/幽灵分组，JOB 必须拒绝

完整链路：`CMDB 建业务 → 导入主机 → 建动态分组 → JOB 引用分组快速执行 → 查状态 → 查日志`，6 个接口串成端到端闭环。
