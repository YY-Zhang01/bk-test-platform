# 131 个用例全景图（分类 + 设计逻辑）

> 用途：面试 / 讲解时，用"一张图 + 一句话"讲清用例怎么分类、为什么这样设计。
> 配套《2026-08-23-用例清单.csv》看每一个用例的名字、作用、设计原因。

## 一、总账（两个正交口径，别混为一谈）

- **用例总数 131** = 119 个测试函数（4 个参数化展开出 12 个额外用例）；另有 17 个 UI 测试（Playwright，本机跑）
- **按"是否依赖蓝鲸"分**：57 现在能跑（unit，不碰蓝鲸）+ 74 等账号（环境层，体验环境 9 月开放）

> 说明：这两个口径是正交的——"能跑/等账号"说的是**要不要联网**，
> 下面"四层金字塔"说的是**测的是什么对象**。unit 测试分散在四层里，
> 不是只有 L1 工具层才有。

## 二、按"测试对象"分四层（金字塔）

```
131 个用例（119 函数）
│
├─ 【L1 工具层】22 个 —— 测"自己写的工具"对不对  ✅ 全都能跑
│     storage 7 + webapp 7 + envs 6 + 文档自检 2（打包拆包、拼参数、分页、存储、Web层、多环境、数字自检）
│
├─ 【L2 分开测】54 个 —— 两系统"各自好不好"  ⏳ 大部分等账号
│    ├─ JOB 六链路（41）
│    │    ├─ 脚本管理 6
│    │    ├─ 快速执行 6  ← 最核心
│    │    ├─ 作业编排 6
│    │    ├─ 定时任务 6
│    │    ├─ 账号 + 高危 7
│    │    └─ 文件 + SQL 10
│    └─ CMDB 链路（13）
│         └─ 业务 → 主机 → 拓扑 → 模型 → 分组 + 写操作（建业务/导主机/建分组）
│
├─ 【L3 连块测】9 个 —— 两系统"连起来对不对"  ⏳ 等账号（端到端这一环）
│     数据契约：CMDB 圈人 → JOB 干活，四个 ID 对不对得上
│     （业务 ID / 主机 ID / 动态分组 ID / 拓扑节点）
│
└─ 【专项横切】34 函数（46 展开）
      ├─ 边界（21 函数，33 展开）—— 参数临界值（超时 0 / 86401 该被拒）
      └─ 安全（13 函数）—— 鉴权 / 越权 / 注入 / 高危命令
```

## 三、每一层"为什么这样设计"

| 层 | 为什么设计它 | 大白话 |
|---|---|---|
| L1 工具层 | 先保证"手"没坏，再谈摸系统 | 螺丝刀没拧紧，怎么拧别人 |
| L2 分开测 | 两个系统各自单独测，好定位问题 | 分开查，出问题知道是谁的锅 |
| L3 连块测 | 单独都好，连起来可能坏（ID 对不上） | 两个零件都好，拼一起可能卡 |
| 边界 | 参数有范围，越界该拦不拦会崩 | 传个 0 超时，机器卡死 |
| 安全 | 危险动作要拦，越权要隔离 | `rm -rf` 拦不住 = 删光服务器 |

## 四、五个维度怎么落到用例里

| 维度 | 落在哪 | 现状 |
|---|---|---|
| 功能 | L1 + L2 + L3 全部 | ✅ 57 能跑，74 待账号 |
| 性能 | Locust 压测脚本 + 定时报告 | 🟡 方案就绪，待账号 |
| 安全 | 专项·安全 + JOB 高危命令链路 | 🟡 骨架就绪，待账号 |
| 边界 | 专项·参数边界 | 🟡 骨架就绪，待账号 |
| 端到端 | L3 连块测（数据契约是其中一环） | 🟡 待账号 |

## 五、面试一句话串起来

> "我 131 个用例分四层：**L1 测自己写的工具（22 个）→ L2 分开测 JOB 六链路和 CMDB（54 个）→ L3 连块测（9 个）→ 再横切边界和安全（46 个展开）**。
> 每一层都对应一个真实风险：工具坏了、单系统坏了、连起来对不上、参数越界、危险命令。
> 按是否联网再切一刀：57 个不碰蓝鲸现在就能跑，74 个等体验账号（9 月开放），诚实 skip 不造假绿。"
