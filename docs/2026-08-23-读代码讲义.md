# 读代码讲义（零基础 30 分钟入门）

> 目标：从"看不懂代码"到"能指着代码说这是干嘛的"。
> 方法：测试代码就 3 个套路。认准套路，任何文件你都读得懂——
> 不需要会写，只需要"读懂大意 + 讲得出来"。

---

## 套路 1：一个测试用例 = 动作 + 断言

看项目里真实存在的一个用例（`tests/test_webapp.py`）：

```python
def test_首页返回平台页面(client):      # ① 函数名：告诉你这条测什么
    r = client.get('/')                  # ② 动作：让测试客户端访问首页
    assert r.status_code == 200          # ③ 断言：返回的状态码应该等于 200
```

逐行翻译：

| 行 | 大白话 |
|---|---|
| `def test_首页返回平台页面(client)` | "这是一条用例，名叫「首页返回平台页面」" |
| `r = client.get('/')` | "模拟浏览器打开首页，把网站返回的东西装进盒子 `r`" |
| `assert r.status_code == 200` | "对答案：盒子里那个状态码，应该等于 200（成功），不是就报错" |

**口诀：中文函数名告诉你测啥，`assert` 告诉你"标准答案"是什么。** 109 个用例，每一个都是这个骨架。

## 套路 2：封装层 = 把 HTTP 细节藏起来

为什么用例里看不到网址、看不到密码？因为那些脏活累活被 `app/api_client.py` 藏起来了。

看这个函数：

```python
def b64_encode(text: str) -> str:
    return base64.b64encode(text.encode('utf-8')).decode('utf-8')
```

翻译：**"把一段文字变成 Base64 编码"**。为什么需要？因为 JOB 接口规定"脚本内容必须 Base64 编码"，所以封装层自动帮你编，用例里写 `content='echo hi'` 就行，不用自己算编码。

再看最核心的一行套路：

```python
def _call(self, api_name, params):
    url = f'{self.esb_host}/api/c/compapi/v2/jobv3/{api_name}/'
    body = {'bk_app_code': ..., 'bk_app_secret': ..., 'bk_token': ...}
    ...
    if not payload.get('result') or payload.get('code') != 0:
        raise JobError(...)
    return payload.get('data')
```

翻译成大白话，`_call` 每次调接口都自动干 3 件事：

1. **拼网址**（把接口名塞进统一格式）
2. **带认证三件套**（账号密码 token，每个请求自动带上）
3. **对答案**（如果服务端说"失败"，立刻抛错，不让错误悄悄溜过去）

这就是**封装**：把"拼网址 + 带凭证 + 检查结果"这些重复动作藏起来，用例只关心业务本身。你面试可以这么讲："我封装了 38 个接口，用例只写业务动作，不碰 HTTP 细节。"

## 套路 3：unit 层 vs 环境层 = "现在能跑" vs "等账号"

看刚写的安全用例里两种写法（`tests/test_security.py`）：

```python
@pytest.mark.unit                          # ← 有这行 = unit 层，现在就能跑
def test_高危检测_脚本内容自动Base64(捕获参数):
    捕获参数['client'].check_script('rm -rf /')
```

```python
def test_高危命令_rm_rf被check_script命中(job_client):   # ← 参数带 job_client = 环境层
    hits = job_client.check_script('rm -rf /')
    assert hits
```

区别就一条：

| 特征 | 属于哪层 | 什么时候跑 |
|---|---|---|
| 有 `@pytest.mark.unit` | unit 层 | 现在就能跑，不等账号 |
| 参数里有 `job_client` | 环境层 | 要真账号，没账号就 skip |

**口诀：看函数参数有没有 `job_client`——有就是环境层（等账号），没有就是本地能跑的。**

---

## 读代码 3 口诀（背下来）

1. **先看函数名**——中文名直接告诉你"这条测什么"。
2. **找 `assert`**——它后面就是"标准答案"，对不上就失败。
3. **看有没有 `job_client` 参数**——有 = 环境层（等账号），没有 = 现在能跑。

记住这 3 条，你就能对着任何一个测试文件说："这个文件测的是 XX，有 N 条用例，其中 unit 层现在能跑、环境层等账号。" 这已经是面试官眼里"看得懂代码"了。
