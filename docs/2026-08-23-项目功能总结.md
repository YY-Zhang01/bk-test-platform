# 项目功能总结（汇报用）

> 用途：跟姐夫 / 面试官汇报时照着讲。一句话 + 功能清单 + 诚实不足。

## 一句话定位

给蓝鲸 CMDB + JOB 两套系统做自动化测试的平台——一台"自动体检机"：
103 个检查用例，一键跑、出报告，测两套系统各自好不好、连起来数据对不对得上。

**在线地址：http://114.55.176.42:8000**（已部署阿里云，可直接打开演示）

## 一、做了什么（核心功能）

### 1. 测试内核：103 个用例（95 函数），分四层

- **L1 工具层（14 个，现在能跑）**：测自己写的工具对不对（Base64 打包、拼参数、分页、存储、Web 层）。
- **L2 用例层（53 个）**：JOB 6 条链路（41）+ CMDB 链路（12，含写操作），分开测、故障隔离。
- **L3 场景层（9 个，等账号）**：两系统连块测，验数据契约（CMDB 圈人 → JOB 干活，四个 ID 对不对得上）。
- **专项横切（19 函数 / 27 展开）**：边界（临界值）+ 安全（鉴权/越权/注入/高危命令）。

> 按"是否联网"另切一刀：35 个 unit 现在能跑（分散在四层里），68 个环境层等账号（9 月开放）。

### 2. 五个测试维度

功能（对不对）、性能（快不快）、安全（漏不漏）、边界（临界崩不崩）、端到端（连起来对不对）。

### 3. Web 平台（已上线，5 个模块）

- **总览**：用例统计、三层金字塔、五维、通过率趋势图；
- **跑测试**：一键跑冒烟/全量/回归，秒出报告；
- **接口调试**：Postman 式在线调 JOB/CMDB 只读接口（写操作白名单拒绝，安全设计）；
- **报告**：历史 HTML 报告归档；
- **AI 生成**：粘贴大模型 key + 选接口（45 个）+ 需求描述 → 生成用例草稿 → **验证可收集** → 通过后并入 tests/（AI 辅助、人来把关）。

### 4. 工程化

- pytest 分层 + marker、CI（GitHub Actions 自动跑 + 覆盖率徽章）、覆盖率 57%、SQLite 历史留痕、Locust 只读压测。

### 5. 技术栈

Python + pytest + FastAPI（单文件内嵌 HTML，零构建）+ SQLite + requests + Locust。

## 二、诚实的不足（主动说，显靠谱）

1. **68 个环境用例是 skip**：蓝鲸体验环境官方停服到 9 月，没账号，选择诚实跳过、不造假绿。
2. **性能/安全是方案+骨架**：代码就绪，但真实数据要等账号。
3. **作业级不是产品级**：没有用例管理界面、数据驱动、多环境、团队协作（那是产品化方向）。
4. **代码 AI 辅助**：但自己读懂了，每个文件干嘛都能讲。

## 三、演示动线（3 分钟）

1. 打开网站 → 总览页讲"金字塔 + 五维"；
2. 点「跑测试」→ 选「冒烟计划」→ 28 个绿（证明能跑）；
3. 点「全量」→ 35 绿 + 73 黄（证明诚实 skip）；
4. 点「AI 生成」→ 展示生成草稿 → 验证可收集（证明 AI 闭环）；
5. 收尾一句："AI 辅助产出思路，人验证把关，这是测试开发在 AI 时代的正确姿势。"
