# 架构升级规划（2026-08-24）

> 目标：把「单文件内嵌前端的阶段 0 平台」升级成「前后端分离 + AI 自愈闭环 + 浏览器自动化」的正经测试平台。
> 三件事：① 前端换 Vue3/Element Plus；② AI 模块参考 ghost 做「生成→跑→自愈」闭环；③ 新增 Playwright 浏览器自动化测试模块。

## 一、目标架构

```
浏览器
  ↓ 调 API（JSON）
┌─────────────────────────────────────────────┐
│ 前端（独立项目 frontend/）                    │
│  Vue 3 + Vite + Element Plus + Pinia + Router │
└─────────────────────────────────────────────┘
  ↓ /api/*
┌─────────────────────────────────────────────┐
│ 后端（app/，FastAPI 纯 API，不内嵌 HTML）      │
│  routers/ 拆路由 + 客户端封装层 + 存储层 + 多环境│
└──────────────┬──────────────────────────────┘
               ↓ sqlite3          ↓ requests → 蓝鲸 ESB
        SQLite（data/platform.db）    被测系统 CMDB / JOB
```

## 二、三大任务

### 任务 A：前后端分离（架构升级）
- 后端：`web_app.py` 去掉内嵌 HTML，改成纯 API（只回 JSON），拆成 `main.py + routers/`
- 前端：新建 `frontend/`，Vue3 + Element Plus 重建全部页面
- 页面清单：总览 / 跑测试 / 接口调试 / 报告 / AI 生成 / 用例库 / **UI 自动化（新增）**

### 任务 B：AI 模块升级（参考 ghost）
- 现状：一次性「文档 → LLM → 代码 → 人工看」
- 目标：闭环「生成 → 自动跑 pytest → 拿 traceback → 喂回 LLM 修 → 重试 N 次 → 人工只看最终结果」
- 关键约束：重试上限（默认 3 次）+ 失败诚实标记「AI 修不动，转人工」，不无限烧钱

### 任务 C：浏览器自动化测试模块（新增，Playwright）
- 平台加「UI 自动化」页：列出/运行 Playwright 测试、看结果
- 复用现有 `tests/ui/` 骨架，升级成平台可管理的模块

## 四、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 | 上手友好、中文资料多、国内主流 |
| 构建 | Vite | 快、现代、Vue 官方推荐 |
| UI 库 | Element Plus | 现成漂亮组件，国内最流行 |
| 状态 | Pinia | Vue3 官方状态管理 |
| 后端 | FastAPI（保持） | 本来就是对的，不换 |
| 数据库 | SQLite（起步） | 单机够用，多人协作再换 MySQL |
| 浏览器自动化 | Playwright（保持） | 已装、一套通吃 Chromium/Edge |

## 五、诚实说代价（升级前必须认）

1. **要装 Node + npm**（已装 v24，OK）
2. **前端从「一个文件」变成「一个项目」**：部署要多一步 `npm run build`
3. **你得学 Vue 基础**，否则以后更看不懂
4. **AI 自愈不是万能**：环境型失败（没账号/没部署）LLM 修不了，必须设上限 + 人工兜底
5. **Playwright 测试要本机跑**（要浏览器），服务器只能存脚本/结果，不能真跑 UI

## 六、兼容与回滚

- 后端 API 路径基本不变（`/api/stats` 等），前端只是换个调用方
- 每阶段独立 commit，出问题可回滚到上一阶段
- 旧单文件 `web_app.py` 在阶段 1 完成前保留不动（作为回退）
